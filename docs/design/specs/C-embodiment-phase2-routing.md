# 方向 C Phase 2:MoE 式路由层(2026-08-30:决策定稿,规格化待评审)

> 定位:承接 `C-embodiment.md`(C-2 双通道审批、C-5 SkillOpt 集成),问题从「装什么」升级为「当前会话激活什么」。全量安装保证冷启动零等待,路由层保证只付当前领域的 token 税。
> 状态:核心决策已定稿,本文只做结构化与实现细节补全,不引入新决策。
> 关联:B-environment.md(env 插件、Fragment 注入)、D-control.md(skill 构成)、E-security.md(audit 目录、审计 hook)。

---

## 1. 动机

**经济学实测(本仓库,2026-08-30)**:全家桶起步税 18.6k token,分解为 omo persona 12k + skill 菜单 5.8k + task 定义 2.1k。sp-router 移植实验(router-modules/)已证明渐进披露可把菜单税从 9158 压到 936(−90%),菜单是当前最大可压缩项。

**但 token 最优 ≠ 发现最优**:菜单砍太狠会触发先验偏差锁死,链条是"模型不知道 skill 存在 → 不调用 → 夜间统计判冷门 → 更不曝光",长尾技能被永久埋没。本仓库定位"帮用户快速配置",新用户不知道自己需要什么,因此**发现优先,收敛 opt-in**。

**路由层目标三条**:冷启动零等待(全量已装,不现场安装);按目录/模式选择性激活(只付当前领域税);夜间对账兜底(漏检最长隔夜被发现,不永久锁死)。

## 2. 核心架构:MoE 式路由

类比 Mixture-of-Experts:

| MoE 概念 | 本设计对应 | 实现物 |
|---|---|---|
| 专家全部驻留模型 | 全局安装全量 harness | setup 一次装齐,冷启动零等待 |
| router 每次只激活 2-3 个专家 | 按目录/模式挂载领域技能集 | gate 插件,目录级门控(§3.1) |
| 门控网络可学习 | 激活策略随使用史收敛 | SkillOpt 夜间审计(§3.4) |
| 未激活专家不删除 | 休眠 skill 不删 | 只降菜单行,文件与安装全在 |

关键不变式:**路由只决定"进不进上下文",不决定"装不装"**。任何路由失败的最坏结果是退回全量清单(贵但完整),不是能力丢失。

### 2.1 常驻/按需分区

判据一条:每次会话都要用 + 占上下文 → 常驻;领域相关 → 按目录。

| 分区 | 内容 | 依据 |
|---|---|---|
| 常驻,0 token | 权限红线、审计 hook | 规则表/静态文件,不进 system prompt(E-1 已定) |
| 常驻,≤200 token | gate 本身、首跑检测 | 路由层自身,见 §3.1 |
| 常驻,12k | omo persona | 只砍内嵌 available_skills 冗余段;纪律段 8.1k 是承重墙,不动 |
| 按目录 | 领域技能集 | gate 挂载,每目录 2-3 个 |
| 按目录 | codegraph | 已天然惰性(工具型,不注册即零成本;语言覆盖是硬门槛,见 E 方向 graphify 判定) |
| 按目录 | GSD 菜单 | 见 §2.2 裁定 |

**available_skills 三份清单并存问题**:persona 内嵌清单(3 项)与 skill 工具 schema 清单(24 项)零交集,加上 gate 路由清单即三份菜单并存。裁定:**砍 persona 内嵌段,全系统统一一张地图**(gate 总目录为唯一菜单,冷门走一行轮换,见 §2.3)。

### 2.2 GSD 裁定(实测修正)

实测 5 次模型调用全是工作型,零次状态查询:模型从不主动调 gsd-help/gsd-progress,激活路径是用户敲 /gsd-*。因此:

- 流程/交付质量层:必选,常驻可用,不随目录卸载;
- 菜单:压成一行,24 条 /gsd-* 命令清单不进 system prompt;
- **流程强制性靠状态注入,不靠菜单**:GSD 项目的会话开始时,env 块注入 .planning 当前位置(在哪个 phase、下一步);模型看状态走流程,用户敲命令推进。实现即 b-modules env 插件加一个 GSD Fragment,零新机制。

### 2.3 多模式用户:菜单演化

不同工作模式(不同项目目录)用不同菜单,不全局平均:

- **聚类单位**:项目目录,同 git 仓库 ≈ 同领域;夜间统计按 directory 聚类,OpenCode session 表已有该字段;
- **热榜**:每模式独立;热门集固化为项目级 .opencode/skills/(切目录 = 切菜单,OpenCode 原生目录级配置承载);
- **休眠不删**:冷门 skill 只降为总目录里一行,全局安装不动,可随时召回;
- **monorepo**:目录粗闸门(仓库根一个领域集)+ 会话内常驻一行总目录兜底,不追求子包级精度;
- **演化节奏**:发现期全量清单 → 按使用史收敛(建议经人审才生效)→ 冷门一行轮换(保留最低曝光,防先验锁死);
- **可解释可关闭**:每次菜单变更能答"为什么"(夜间报告引用计数);一键 opt-out 回全量。

## 3. 组件规格

### 3.1 gate(目录网关插件)

- **职责**:会话开始读 directory 并查该目录路由状态;未初始化 → 触发首跑 init;已初始化 → 挂载对应领域技能集。挂载用渐进披露:只注入名称 + 一行时机,正文按需 Read,手法照抄 sp-router。
- **输入**:当前 working directory;目录路由状态文件(首跑产物);常驻总目录(全量一行式清单)。
- **输出**:路由块(激活集清单 + vault 路径 + 总目录一行),常驻 ≤200 token;决策写 routing.jsonl(§3.3)。
- **挂载点**:本地插件,plugins/ 顶层 .ts 是唯一正确形态;**.mjs 是毒丸,plugin 数组只认 npm 包**,本地挂法参照 rtk.ts 先例。
- **失败降级**:gate 加载失败、状态文件损坏、目录不识别 → 注入全量总目录(退回 sp-router 形态,贵但零能力丢失);gate 自身报错不阻塞会话启动。

### 3.2 首跑 init skill

- **职责**:新目录首次会话时识别领域,产出该目录激活集。
- **输入**:目录特征,含语言(扩展名统计)、框架(配置文件指纹:package.json、go.mod、Cargo.toml、requirements.txt 等)、git remote(仓库归属)、既有 .opencode/ 目录(用户已手工配置则尊重不覆盖)。
- **处理**:扫描 → 生成建议(领域 + 激活集 + 置信度);置信度高 → 静默默认,事后一句话声明,可反悔;置信度低 → 问一次并附推荐答案;**识别不了才问人,绝不强制问卷**。
- **输出**:目录路由状态文件;决策入 routing.jsonl;交互预算 ≤3 次(含一键确认)。
- **挂载点**:skill 形态,由 gate 在首跑时点名加载;扫描逻辑复用 b-modules env-profile 探测模式(只读静态,防 EDR 口径,对齐 B §3 边界)。
- **失败降级**:扫描失败 → 静默挂通用集,并在 routing.jsonl 标记 unclassified;用户可随时重跑 init 改判。

### 3.3 路由日志(routing.jsonl,新增)

- **职责**:gate 每次决策留痕。没有它,SkillOpt 夜间审计是瞎的:只见干了什么活,不知路由到了谁。
- **输入**:gate 决策事件(会话开始挂载、首跑触发、降级触发)。
- **输出**:JSONL 追加,一行一会话,字段含时间戳、directory、决策类型(init/mount/degraded)、激活集、模式标识、会话 ID。
- **挂载点**:复用 audit 目录(e-modules audit-init.sh 同目录、同轮转策略、同保留期),文件名 routing.jsonl;observe-only 写入,不阻塞会话。
- **失败降级**:写失败 fail-open(路由照常,记 alerts);夜间报告对缺日志区间显式声明置信度降级,不假装完整。

### 3.4 SkillOpt 夜间审计(门控学习)

- **职责**:对账"干了什么活"(audit.jsonl)vs"路由到了谁"(routing.jsonl),产出菜单调整建议。MECE 两类:
  - **漏**:audit 里出现领域性工作模式,但 routing 显示无对应专家被激活或调用。点名现有 skill 补进激活集;确实没有 → 自动起草新 skill 进 skill-drafts/(草稿区,不生效);
  - **重**:多个 skill 覆盖同一工作模式 → 合并建议。
- **输入**:routing.jsonl + audit.jsonl(全工具调用)+ session 表 directory 字段(聚类);对账骨架复用 d-modules opstate 的 watch-diff-reconcile 模式。
- **输出**:夜间报告,三类建议(点名、起草、合并)各附证据计数与目录;起草文件落 skill-drafts/。
- **挂载点**:SkillOpt-Sleep 夜间管线(C-5 已定,MIT,本地跑);与 mem0 通道①互不混流,归属 C-2 改进通道。
- **失败降级**:某目录数据不足(会话数低于阈值)→ 跳过不产出;报告整体失败 → 菜单原样保留,零行为变更。
- **硬边界:产物全部进双通道人审(改进通道,重审批),夜间审计永不直接改激活集**。

## 4. 数据流

```
会话开始 → gate ─┬─ 无状态文件 → init skill 扫描 → 确认/静默默认
                 │                → 写状态文件 → routing.jsonl(init)
                 └─ 有状态文件 → 注入激活集 + 总目录一行 → routing.jsonl(mount)
会话中:audit hook 记全工具调用(干了什么活)→ audit.jsonl
夜间:routing.jsonl × audit.jsonl × session.directory
      → SkillOpt 对账 → 报告 + skill-drafts/ → 人审
      → 更新项目级 .opencode/skills/(菜单演化)→ 下次会话挂载新菜单
```

三条主链路:

1. **首跑链**:gate 发现新目录 → 点名 init → 扫描出建议 → 一键确认或静默默认 → 落状态文件并挂载;
2. **常态链**:gate 读状态文件 → 注入激活集与总目录 → 模型命中场景按需 Read skill 正文 → audit 与 routing 双日志并行留痕;
3. **夜间链**:三源聚类对账 → 漏/重建议 + 起草落草稿区 → 人审通过才更新项目级菜单。

GSD 状态注入独立于三链:env 插件 GSD Fragment 每会话读 .planning 注入当前位置,与 gate 互不依赖。

---

## 5. 边界(不做)

- 不自动启用/禁用任何 skill:生效变更全走 C-2 双通道人审,夜间只产建议;
- 不动 persona 纪律段(8.1k,承重墙),只砍其内嵌技能清单冗余段;
- 不删休眠 skill(只降菜单行);不做 monorepo 子包级精细路由;
- 不引入付费服务:夜间审计本地跑,SkillOpt 与 mem0 均开源(MIT/Apache-2.0,C-5 已核);
- 不碰模型层路由:subagent 模型跟随是 omo 配置层议题(B 未决记录),本 spec 只管上下文菜单层;
- 不改 setup 安装语义:全量安装仍是默认,路由是上下文优化,不是安装裁剪。

## 6. 验收标准(可测)

| # | 标准 | 测法 |
|---|---|---|
| 1 | 新目录首跑 ≤3 次交互;高置信目录 0 交互(静默默认 + 声明) | Docker 矩阵跑典型目录(TS/Py/bash/md-only),数交互轮次 |
| 2 | gate 常驻 ≤200 token | 注入块 token 计数,对照 18.6k 基线 |
| 3 | 路由日志覆盖 100% | 任一会话启动后 routing.jsonl 必有对应行(init/mount/degraded 三态其一),抽会话比对 |
| 4 | 夜间报告三类建议齐备 | 构造含漏与重的样本数据,报告须含点名、起草(落 skill-drafts/)、合并三类,各附证据 |
| 5 | 起步税只含激活领域 | 未激活领域的 skill 描述不出现于 system prompt,token 计数比对 |
| 6 | 降级不丢能力 | 破坏状态文件/禁用 gate,会话仍持全量总目录且功能可用 |
| 7 | 休眠可召回 + 可关闭 | 冷门降行后总目录仍在;opt-out 一键回全量;恢复后调用正常 |
| 8 | 注入幂等 | 同会话重复触发不重复注入(sp-router 幂等手法) |
| 9 | GSD 状态注入按需 | 有 .planning 的项目会话首消息 env 块含当前 phase 与下一步;无 .planning 项目零注入 |
| 10 | 统一一张地图不丢项 | 砍 persona 内嵌段后,统一总目录 ∪ skill 工具 schema = 原三份清单并集 |

## 7. 已知折衷(诚实清单)

- **发现延迟隔夜**:漏检最长 24h 盲区(等夜间对账);换来起步税立降,接受;
- **gate 单点**:gate 故障则退全量菜单(贵但完整);本地插件形态脆弱(顶层 .ts 唯一正确,.mjs 毒丸,plugin 数组只认 npm 包),OpenCode 升级可能破坏挂载,验收 #6 兜底;
- **monorepo 粗闸门**:目录级 gate 无法区分子包领域,靠会话内总目录一行兜底,精度换简单;
- **先验偏差只缓解不消除**:菜单收敛仍可能压长尾发现;缓解手段 = 发现期全量 + 冷门一行轮换 + 夜间对账 + 收敛 opt-in,残余风险如实告知用户;
- **token 最优 ≠ 发现最优**:按产品定位选发现优先,起步税高于理论最优值,这是决策不是疏漏。
