## 诚实的结论

### 1. 用户的质疑在这类任务上成立:不是帕累托

**通用任务上,裸 opencode 全面碾压**:成功率相同(4/4),快 3-8 倍,token 省 1-2 个数量级。原因:
- glm-5.3 本身够强(裸臂的内置 Explore 子代理、注入免疫力、awk 直接统计不倒文件,全是模型能力不是配置能力)
- omo+sp 插件上下文每任务固定注入 ~4-25k token,这是纯开销
- 重上下文还诱发过度工程:臂b 在 CSV 统计任务上要下载依赖工具,把自己搞到超时

### 2. 全家桶的真实价值不在"任务成功率",在别处

按证据强度排:
1. **保障性(非成功率)**: 权限红线是确定性拦截(不依赖模型当天心情)、审计 JSONL 是取证链、AGENT-CARD/合规是组织需求。BX2 三臂都拒绝了注入——但那是 glm-5.3 的判断力;红线层的价值 = 模型被更强的社工骗过时的兜底 + 可审计。**买的是保险,不是跑分**
2. **RTK 输出压缩**: BX4 臂c(10127) vs 臂b(25162)省 60%——但裸臂用 awk 根本不产生大输出。RTK 只在"必须消化大输出"的任务(构建日志/测试矩阵)有真实收益
3. **专属能力扩展**(本次未触发差异): webmap(截断后知识/llms.txt 站点)、codegraph(大型代码库结构查询)、GSD(多阶段项目管理)、跨会话记忆——这些是"没有就做不到"的能力,不是"做得更好"
4. **omo 专业子代理**(oracle/librarian等): 本项目开发全程实际依赖(评审/调研/平行作业)——但其价值在**编排工作流**,不在单任务

### 3. 建议(按用户"省 token"优先级)

- **轻度用户/纯任务场景**: 裸 opencode 就是最优解,装一堆插件是负优化
- **推荐分层安装**: 把 setup 拆成"基础层(bun/opencode/镜像源/model 默认)"与"增强层(omo/安全/webmap/rtk)"二级选装,默认只装基础层——增强层按需 opt-in
- 增强层的正确卖点: 审计合规(组织)、大输出任务(RTK)、大型代码库(codegraph)、多阶段项目(GSD)、长期协作(记忆/画像)——**不是**"装了更聪明"

## 已知局限(防止过度解读)

- 每任务单次运行(模型方差未平均;BX1-BX4 结论方向一致,置信度尚可但不完美)
- 任务偏小(分钟级);天级多阶段项目可能反转(正是 GSD/记忆的主场,未测)
- 臂c 的 webmap/codegraph 能力无对应任务(找不到 glm-5.3 知识截断的诚实考题);注入只测了伪装社工一种
- token 为 input 累计(含上下文重读),相对比较有效,绝对值有重复计数
